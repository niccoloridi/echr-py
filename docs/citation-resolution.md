# Authoritative citation resolution

Citation networks are only as defensible as their document identities. In
HUDOC, an application number identifies an application, not necessarily one
judgment or decision. The same application can have admissibility, preliminary-
objections, merits, Article 50, just-satisfaction, revision,
friendly-settlement, and striking-out documents. It can also have separate
English and French HUDOC rows.

`echr-py` therefore treats SCL resolution as bibliographic entity resolution.
It never zips `sclappnos` to SCL strings and never accepts an application
number or fuzzy title by itself.

## The identifiers are not interchangeable

| Field | Meaning | Resolution role |
| --- | --- | --- |
| Application number (`appno`) | An application or grouped applications | Candidate discovery only unless date/type/phase makes one document unique |
| ECLI | Canonical identity of a Court document | Preferred graph node identity; ENG/FRE rows collapse here |
| HUDOC item ID | One HUDOC record, often language-specific | Exact identifier and fallback node identity where no ECLI exists |
| SCL | HUDOC's formatted, free-text cited-case list | The source mentions to parse and audit |
| `sclappnos` | Unordered application-number pool associated with SCL | Candidate discovery only; never positionally paired with SCL |
| `extractedappno` | Numbers found anywhere in the body | Never used for authoritative resolution |
| Reporter locator | `Series A no. 58`, `Reports 1996-VI`, `ECHR 2004-X`, `D.R. 65, p. 59`, etc. | Bibliographic evidence; unique locators can identify a document |

## Authority and provenance

The primary concordance is generated from the Court's official master list of
exact case-law references:

<https://www.echr.coe.int/documents/d/echr/case_law_references_eng>

The importer also supports the official French edition:

<https://www.echr.coe.int/documents/d/echr/Case_law_references_FRA>

An authority JSON records its source URL, edition date, import time, parser
version, coverage, and source PDF SHA-256. Ordinary online resolution enriches authority entries against
HUDOC metadata and retains ECLI, item ID, application numbers, date, document
type, phase, language variants, and respondent in the output target catalog.

The repository includes the official English and French editions updated
through **27 July 2026** in `hudoc_py/data/citation_authority.json` and
`hudoc_py/data/citation_authority.csv`: 42,161 language-specific official rows
and six transparent reviewed supplements, for 42,167 packaged rows. The
41,676 safely paired official entries carry one cross-language equivalence link
each. Non-unique Reports/ECHR volumes are never used as identity keys.
Its coverage is `full`; each source record retains its language, URL, edition
date, retrieval timestamp, entry count, and exact PDF SHA-256. The packaged
authority was generated by parser version **7**. Before a new study or final
publication, check the official link. If the Court has published a newer
edition, download it in a browser and build a new hash-verified authority:

| Language | Official rows | Source PDF SHA-256 |
| --- | ---: | --- |
| English | 21,083 | `1615883e31eb1a23ee4e6df3c765124dac6a60774a3c38b697849a5e78fa7b2d` |
| French | 21,078 | `c7169b8c1718e17fd6e43df652758853a88f0aff710f047f616c0f990ab5a9c5` |

```bash
pip install -e '.[citations]'

echr-py citations authority import \
  --pdf Case_law_references_ENG.pdf \
  --language eng --retrieved-at 2026-08-20T13:51:51+01:00 \
  --out authority-eng/
echr-py citations authority import \
  --pdf Case_law_references_FRA.pdf \
  --language fra --retrieved-at 2026-08-20T13:46:19+01:00 \
  --out authority-fra/
echr-py citations authority merge \
  --authority authority-eng/ --authority authority-fra/ --out authority/
```

Authority v2 records provenance separately for each language edition and
preserves each official language form as its own entry. Equivalence links
require an application number or unique Series A locator plus compatible date,
document type, procedural phase, and Grand Chamber status. Each key must contain
exactly one English and one French row; translated titles and non-unique
Reports/ECHR volumes never cause a merge. Loading and merging older authority
v1 artifacts remains supported.
The legacy `citation_authority_eng.*` snapshot is retained for file-level
compatibility, but `load_authority()` uses the bilingual v2 authority by
default.

The Court's server may present a browser challenge, so automated download is
not required and the command always accepts a local PDF. The importer detects
the `Updated until` date when present and writes both
`authority/citation-authority.json` (the runtime source of truth) and
`authority/citation-authority.csv` (a flat human-readable mirror).
Pin `--retrieved-at` when producing a committed or archived authority; with the
same PDFs, parser version, and timestamp, both artifacts are byte-reproducible.

No LLM is used to parse the PDF or resolve citations. Import is deterministic
local text extraction with `pypdf`; resolution is deterministic evidence logic
plus cached public HUDOC metadata queries. It has no token cost and requires no
LLM API key. Human review – not computation – is the material cost for difficult
references.

Every official template contains `§ ...`, indicating where a researcher should
insert paragraph numbers. The parser uses this slot to validate logical PDF
rows, removes it from bibliographic identity, and stores any real `§ 22` or
`§§ 22-24` pointers separately on the mention. This prevents paragraph detail
present in source text – but absent from SCL – from breaking an otherwise exact
match.

Pin the authority JSON and its source SHA-256 for reproducible analysis. Check
the official link and re-import before starting a new corpus or finalizing a
publication if a newer edition is available. Keep old authority versions when
reproducing an earlier result rather than overwriting them silently.

HUDOC also contains European Commission decisions and reports, although the
historical collection has publication gaps. A reference confirmed by the
authority but absent from HUDOC receives `target_not_in_hudoc`; it is not
silently relabelled as a nearby Court judgment.

## Parser and evidence hierarchy

Every SCL fragment becomes a `CitationMention` containing stable mention and
reference hashes, unmodified text, source identity/language, cited title,
explicit identifiers, full or partial date, document kind, procedural phase,
Grand Chamber marker, reporter fields, cited paragraphs, and optional source
paragraph context.

Resolution uses this hierarchy:

1. reviewed manual override;
2. explicit ECLI or item ID;
3. exact official-authority citation or unique reporter locator;
4. explicit appno plus a unique date/type/phase match;
5. reporter locator plus a unique title/date/type match;
6. title/date/type match within the unordered `sclappnos` pool;
7. full HUDOC metadata discovery;
8. aliases and source context for candidate generation only.

The acceptance boundary is strict:

- a unique Series A number can resolve through the authority;
- `ECHR 2004-X` or another multi-document volume cannot resolve alone;
- appno alone cannot choose among procedural documents;
- fuzzy title similarity ranks candidates but never creates an edge;
- future-dated targets are rejected;
- only an identical source and target ECLI/item ID is a self-edge;
- bilingual rows with the same ECLI become one node;
- several grouped appnos resolving to one ECLI still become one target.

Each mention receives exactly one status:

| Status | May enter the graph? | Meaning |
| --- | --- | --- |
| `resolved_identifier` | Yes | Explicit ECLI or item ID |
| `resolved_authority` | Yes | Official exact citation/reporter authority plus target metadata |
| `resolved_metadata` | Yes | Unique corroborated HUDOC metadata match |
| `resolved_override` | Yes | Reviewed, validated override |
| `ambiguous_document` | No | More than one procedural document remains plausible |
| `unresolved_reference` | No | No uniquely acceptable target; `method` records the concrete conflict or discovery failure |
| `target_not_in_hudoc` | No | Identified target is absent; a reviewed authority absence may be a documented exclusion, otherwise review remains required |

## End-to-end workflow

Build source cases and resolve one hop of directly cited targets:

```bash
echr-py corpus build \
  --article 3 --respondent ITA --limit 1000 \
  --citations \
  --citation-authority authority/ \
  --citation-overrides citation-overrides.csv \
  --out corpus/
```

Or resolve an existing file explicitly:

```bash
echr-py citations resolve \
  --in corpus/cases.parquet \
  --authority authority/ \
  --overrides citation-overrides.csv \
  --out corpus/citations/
```

For a reproducible offline rerun, provide a local HUDOC metadata catalog and
disable lookups:

```bash
echr-py citations resolve \
  --in corpus/cases.parquet \
  --catalog hudoc-target-catalog.parquet \
  --authority authority/ --offline \
  --out corpus/citations/
```

The resolution directory contains:

| Artifact | Contents |
| --- | --- |
| `mentions.parquet` | Every parsed SCL mention and its status |
| `targets.parquet` | Canonical resolved HUDOC documents |
| `candidates.parquet` | Candidate evidence, especially for review |
| `edges.parquet` | Accepted source→target edges, with repeated mentions aggregated as `citation_count` |
| `nodes.parquet` | Canonical ECLI/item-ID document nodes |
| `lookup-cache.jsonl` | Resumable HUDOC metadata lookups |
| `resolution-report.json` | Authority provenance, method/status counts, scope, and completeness |

Run `citations locate` after resolution to add paragraph-aware occurrence
artifacts without changing any accepted edge or `citation_count`. The source
and target layers, portable schema, typography rules, and offline cache
contract are documented in [citation-occurrences.md](citation-occurrences.md).

No unresolved mention is omitted from `mentions.parquet`, even though it is
excluded from `edges.parquet`.

The report separates `resolved`, raw `unresolved`, `documented_exclusions`, and
`review_required`. A reviewed Registry-only or historically unpublished target
remains outside the graph but counts as methodologically accounted for. An
ordinary failed lookup or missing catalog target does not: it still increments
`review_required`. `complete` becomes true only when review-required mentions,
placeholder nodes, and unidentified source documents are all zero.

## Review workflow

Generate a read-only review page and an override template:

```bash
echr-py citations review \
  --resolution-dir corpus/citations/ \
  --out citation-review.html \
  --csv citation-overrides.csv
```

The HTML places the printed reference, source context, parsed evidence, target
metadata, evidence conflicts, and HUDOC links side by side. It intentionally
does not write decisions. Fill the CSV with the source ECLI or item ID,
reference hash, exact target ECLI or item ID, reviewer note, and review date,
then rerun `citations resolve`. Source-specific overrides outrank reusable
reference aliases, and every override target must exist in the target catalog.

Do not interpret every `unresolved_reference` as “not enough information.” The
resolver records concrete methods such as `printed application number
conflicts with HUDOC metadata`, `printed date conflicts with HUDOC metadata`,
`printed document kind conflicts with HUDOC metadata`, `only placeholder HUDOC
target found`, or `no corroborated HUDOC target found`. A contradictory printed
date is intentionally different from a genuinely under-specified citation.

## Measurement-grade graphs

Metrics fail closed unless `resolution-report.json` has `complete=true`:
`review_required`, `placeholder_nodes`, and `unidentified_source_documents`
must all be zero. Resolved mentions and reviewed documented exclusions both
count toward completeness; exclusions never become graph edges.

```bash
echr-py graph metrics \
  --citations corpus/citations/ \
  --weight citation_count \
  --out corpus/citation-metrics.parquet

echr-py graph html \
  --citations corpus/citations/ \
  --out corpus/citation-network.html

echr-py graph gexf \
  --citations corpus/citations/ \
  --weight citation_count \
  --out corpus/citation-network.gexf
```

`graph metrics` writes a metadata sidecar identifying authority provenance,
resolution rate, one-hop scope, weighting, and whether the output is
measurement-grade. `--allow-incomplete` is diagnostic only: it labels output
provisional and must not be presented as a complete network.

In the Python API the same contract is explicit:

```python
result = await resolve_citations(
    source_cases,
    authority=authority,
    catalog=local_catalog,
    client=hudoc_client,
    overrides=overrides,
)

result.require_complete()
graph = CitationGraph.from_resolution(result)
metrics = graph.metrics_dataframe(weight="citation_count")
```

`CitationGraph.resolve()` remains a strict offline convenience for old code.
It may collapse language rows that share one ECLI, but it refuses to choose the
first row when one appno maps to multiple documents. It does not provide the
authority provenance needed for a measurement-grade published network.

## Migration from the legacy graph path

| Legacy | Authoritative replacement |
| --- | --- |
| `CitationGraph(cases).resolve()` | `await resolve_citations(...)`, then `CitationGraph.from_resolution(result)` |
| `echr-py graph metrics --in cases.parquet` | `citations resolve`, then `graph metrics --citations …` |
| `echr-py graph html --in cases.parquet` | `citations resolve`, then `graph html --citations …` |
| `--use-extracted-appno` | Removed from the measurement workflow; inspect parsed mentions/candidates instead |
| appno-keyed graph nodes | normalized ECLI nodes, falling back to namespaced HUDOC item IDs |
| one edge per SCL row | one aggregated source-target edge plus retained mention IDs |

Existing legacy commands still parse for diagnostics, but graph outputs require
`--allow-incomplete` and are explicitly provisional because no authority or
review completeness report exists.

## What “100% complete” means

It means every reference included in the graph has an exact authoritative,
metadata-corroborated, or reviewed document identity, and every excluded
reference is still present in the audit artifacts with a status. It does not
mean forcing every historical printed reference onto a HUDOC record. Genuinely
unpublished Commission material remains a documented coverage exclusion.

## Release validation audit

The parser and then-current resolver were tested on a fixed live-HUDOC sample,
not only on synthetic fixtures. The sampling query selected the 100 most recent English
Court judgments, decisions, and advisory opinions for which `scl:*` was
present, sorted by `kpdate Descending`. At collection time HUDOC reported
19,900 matching source records; the selected sources ran from **3 March 2026**
through **9 July 2026**.

| Audit measure | Result |
| --- | ---: |
| Source documents | 100 |
| Parsed SCL mentions | 2,492 |
| Automatically resolved | 2,479 (99.5%) |
| `resolved_metadata` | 1,714 |
| `resolved_authority` | 765 |
| `ambiguous_document` | 1 |
| `unresolved_reference` | 11 |
| `target_not_in_hudoc` | 1 |
| Accepted targets conflicting with an explicit appno | 0 |
| Reviewed authority concordances overriding a conflicting HUDOC index date | 1 (Temeltasch, D.R. 31 p. 130) |
| Paragraph fields contaminated by following dates | 0 |
| Placeholder nodes after ECLI-language reconciliation | 0 |
| HUDOC lookup errors | 0 |

The audit used authority parser version 6, the 10 July 2026 authority edition,
and source SHA-256
`d5ded3abd3de67cdc3c0dd43b37de0b80f8558e40621e75d63c03faa2f3b07ee`.
The resolver queried HUDOC, retained 14,000-plus returned metadata rows in
`lookup-cache.jsonl`, and then reproduced the same resolution deterministically
offline.

Validation was both mechanical and semantic. Every accepted mapping was
checked for explicit-appno and exact-date contradictions. A stratified sample
of authority, metadata, reporter-only, low-title-similarity, Commission, and
procedural-phase mappings was read as raw citation → target ECLI, and every
unresolved reference was inspected. That review found and led to fixes for:

- CLIN summaries and execution resolutions incorrectly competing with the
  underlying judgment;
- dates before the official `§ ...` slot being dropped during PDF import;
- space-separated reporter volumes and Unicode minus signs;
- days in malformed dates being captured as paragraph numbers;
- generic HUDOC titles for Article 41/50 and striking-out documents;
- a non-unique ECHR volume briefly allowing an unrelated same-volume target;
- English placeholder source rows where a non-placeholder ECLI sibling exists.
- English placeholder target rows requiring a substantive ECLI sibling;
- Protocol 16 request identifiers, bilingual advisory opinions, and legal
  summaries that are not independent document targets;
- historical `decision of the Commission, Reports 27` grammar;
- official ECHR/Reports citations distinguishing merits judgments from
  admissibility decisions sharing an appno;
- concrete conflict diagnostics instead of the generic “insufficient
  evidence” fallback;
- the Temeltasch D.R. 31 concordance, checked against the scanned Commission
  report despite HUDOC's inconsistent index date.

A mention-by-mention differential audit compared the preceding resolver output
with parser version 6. Seventeen previously held mentions gained authoritative
targets, while **zero previously resolved mentions changed target ECLI/item
ID**. Nine already-correct targets changed only their method classification
between metadata and authority evidence.

The earlier same-volume issue is important: the broad match was rejected and
the acceptance rule tightened before release. In that audited run there were no
metadata-only accepted appno or exact-date contradictions. The separately
labelled Temeltasch authority mapping is the one reviewed exception to the
HUDOC-date check.

The dated 99.5% figure is **automatic coverage**, not current-code accuracy or
measurement completeness. It used parser version 6 and the 10 July English
authority; later parser, authority, and title/phase gates require their own
fresh denominators. The 13 held references do not enter `edges.parquet`: one
remains ambiguous after a
printed-date conflict, eleven have explicit printed appno/date/document-kind
conflicts with HUDOC, and one 2001 admissibility decision was expressly
obtainable from the Registry but is not published as a HUDOC target. A reviewer
must decide the twelve conflicts with `citations review`; the Registry-only
decision is already a documented coverage exclusion. Only after the remaining
review decisions are recorded will metrics run without a provisional override.
